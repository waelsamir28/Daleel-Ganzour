# الجولة ٢٨ — تذكير تلقائي بالاستكمال (بعد ٣ أيام، إشعار واحد لكل مهنة)

## الفكرة
الإدارة تطلب استكمال بيانات مهنة → لو صاحبها مردّش خلال **٣ أيام**، يوصل له
**إشعار واحد تلقائي** داخل التطبيق (يظهر في «إشعاراتي»). لو الإدارة بعتت طلب استكمال
جديد، العدّاد يبدأ من جديد ويُسمح بتذكير واحد جديد — ومفيش تكرار لنفس الطلب.

## المنطق (src/lib/completion-reminder.ts — نقي ومُختبر)
- `COMPLETION_REMINDER_DAYS = 3`.
- `completionReminderDecision(service, now)` → `due` أو السبب:
  `not-requested` (مش مطلوب/بقى submitted أو done) · `no-date` (بيانات قديمة) ·
  `too-early` (أقل من ٣ أيام) · `already-reminded` (اتبعت تذكير لنفس الطلب).
- `completionReminderMessage()` نص مختصر + أيام الانتظار.
- `dueReminderCount()` لعدّاد اللوحة.

## التخزين
عمودان جديدان على `directory_services`:
`completion_requested_at` (وقت آخر طلب — أساس العدّاد) و`completion_reminder_at`
(وقت آخر تذكير)، مع `SCHEMA_VERSION = 2026-11-02.12`.
- «استكمال» و«استكمال الكل» يضبطان `completion_requested_at = now` ويمسحان التذكير القديم.
- اعتماد الاستكمال («تم التنفيذ») يمسح التاريخين.
- إرسال استكمال من المهني (submitted) يوقف التذكير لأن الحالة مش `requested`.

## الـ API
`PATCH /api/admin { type:"service", action:"completion-reminders" }`
→ يمشي على المهن `requested`، ويبعت إشعار `provider` لكل مستحق، ويحدّث `completion_reminder_at`.
متاح للأدمن والمشرف.

## الواجهة
- **تلقائي:** أول ما المسؤول يفتح اللوحة وفي مهن مستحقة، الطلب بيتبعت لوحده
  (محاولة واحدة لكل جلسة متصفح، والمنع الحقيقي على الخادم).
- شريط في تبويب «طلب استكمال بيانات»: «N مهنة عدّى عليها ٣ أيام من غير رد — إشعار واحد تلقائي»
  مع زر **«إرسال التذكير الآن»** لو حب يبعته فورًا.
