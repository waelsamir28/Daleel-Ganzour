# الدفعة ١١: بحث أذكى بالعربية + أرقام استخدام حقيقية

## ١) البحث بقى يتعامل مع الأخطاء الإملائية

- `editDistanceAtMost(a, b, max)` و`isCloseWord(word, candidate)` في `src/lib/catalog.ts`
  (بدون مكتبات خارجية، مع توقف مبكر حتى يبقى سريع).
- `matchesServiceQuery` بقى بيعمل ثلاث مراحل:
  1. مطابقة جملة البحث كما هي.
  2. مطابقة كل الكلمات.
  3. مطابقة «قريبة» تتحمّل غلطة حرف واحد للكلمات ٣–٥ حروف، وغلطتين للكلمات الأطول.
- `suggestSpecialties` بقى بيحسب نصف نقطة للمطابقة القريبة، فالتخصص القريب بيظهر في الاقتراحات.

أمثلة: «سباكه» / «سباك» / «سبااك» / «كهربا» / «نجر» كلها بتوصل لنفس المهني.

## ٢) إحصاءات استخدام حقيقية (على الخادم)

قبل كده كانت الأرقام محفوظة في متصفح الزائر فقط. دلوقتي:

| الجزء | الملف |
| --- | --- |
| جدول `directory_service_hits` (مشاهدات + نقرات تواصل لكل مهني) | `src/db/schema.ts` + ترحيل تلقائي في `src/lib/directory.ts` |
| `recordServiceHit(serviceId, kind)` | `src/lib/directory.ts` |
| استقبال `serviceId` في عدّاد الزيارات | `src/app/api/hits/route.ts` |
| `GET /api/insights` (أدمن/مشرف): الإجماليات + الأكثر تواصلًا + الأقسام النشطة | `src/app/api/insights/route.ts` |
| بطاقة «أرقام الاستخدام الحقيقية» في الإحصاءات | `src/components/admin-usage-insights.tsx` |

- فتح بطاقة المهني = مشاهدة واحدة (مرة لكل جلسة متصفح).
- أول ضغطة اتصال أو واتساب = تواصل واحد (الاتصال والواتساب على نفس البطاقة ما يتحسبوش مرتين).
- الأرقام مجهولة تمامًا: مفيش اسم أو رقم زائر أو IP مخزّن.
