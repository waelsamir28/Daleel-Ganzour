# كارت المهني · بيانات SEO للمهن · مراقبة أخطاء الموقع

ملف مرجعي للثلاث ميزات المضافة في هذه الجولة (١ · ٧ · ٩ من قائمة الاقتراحات).

## ١) كارت المهني كصورة (Share Card)

**إيه ده؟** كل مقدم خدمة يقدر يطلّع كارت من بياناته (الاسم + التخصص + المنطقة + الأرقام +
QR لصفحته) ويحفظه صورة على موبايله، ويرسله لعميل، أو يطبعه ويعلّقه في المحل.

**فين يلاقيه؟**

- صفحة المهني/العضو `/profile/<id>` ← زر **«كارت جاهز كصورة»** (أيقونة الكارت في شريط الأدوات).
- كارت الخدمة في الدليل ← أيقونة QR («بطاقة العمل الرقمية») ← زر **«حفظ الكارت كصورة»**.

**المواصفات:** 1080×1350 (4:5) — نفس مقاس صور السوشيال، بهامش آمن للستوري.

**الأزرار:** مشاركة كصورة (Web Share) · حفظ على الجهاز · نص على واتساب · طباعة.

**الكود:**

| الملف | الدور |
| --- | --- |
| `src/lib/share-card.ts` | منطق نقي: تنظيف الأرقام، اسم الملف، نص المشاركة، سطور الكارت، التحقق من صلاحية البيانات |
| `src/components/share-card-modal.tsx` | الرسم على Canvas + المعاينة + أزرار الحفظ/المشاركة/الطباعة |

> لو زر «مشاركة كصورة» مش مدعوم على جهاز الزائر، بيرجع تلقائيًا لتنزيل PNG.

## ٧) بيانات SEO لكل مهني + صورة مشاركة ديناميكية

- **JSON-LD:** صفحة كل مهني فيها بيانات منظَّمة `LocalBusiness` (أو `Person` لو عضو بدون مهنة)
  فيها الاسم والتخصص والمنطقة والرقم والتقييم الحقيقي — قبل كده كانت صفحة من غير بيانات.
  والرئيسية فيها `WebSite` + `LocalBusiness` للدليل نفسه.
- **صورة مشاركة لكل مهني:** `/profile/<id>/opengraph-image` تُولَّد على الخادم (1200×630) بنفس
  هوية الدليل — فالرابط يبان في واتساب/فيسبوك ببطاقة صاحبها بدل صورة عامة.
- **canonical + twitter card** على صفحة الملف.

| الملف | الدور |
| --- | --- |
| `src/lib/seo.ts` | `profileSeo`, `profileJsonLd`, `siteJsonLd`, `jsonLdText`, `profileCanonicalUrl` |
| `src/app/profile/[id]/page.tsx` | metadata + وسم `application/ld+json` |
| `src/app/profile/[id]/opengraph-image.tsx` | صورة المشاركة (خطوط Cairo محلية — بدون طلب شبكة) |
| `src/app/page.tsx` | JSON-LD للموقع في الرئيسية |

**ملاحظة تقنية:** محرّك رسم الصور (satori) بيرصّ الكلمات من الشمال لليمين، فالصورة بتعكس ترتيب
الكلمات (`rtlWords`) قبل الرسم حتى تظهر الجملة العربية صح.

## ٩) مراقبة أخطاء الموقع

كل خطأ JavaScript في متصفح الزائر، أو فشل صفحة (`app/error.tsx`)، بيوصل بلاغ مجهول للإدارة.

- **مفيش بيانات شخصية:** الرسالة بتتنظف من أرقام الهواتف والروابط والمفاتيح (`redactErrorText`)،
  ومفيش كوكيز ولا أسماء.
- **تجميع:** كل خطأ له بصمة (`errorFingerprint`)، فالأخطاء المتكررة تظهر مرة واحدة بعدد التكرار.
- **حدود:** بلاغان لكل تحميل صفحة، ونفس الخطأ ما يتبعتش مرتين في نفس الجلسة، و20 بلاغًا/جهاز كل 15 دقيقة.
- **تنبيه واتساب:** مرة واحدة كل ساعة لنفس الخطأ (نوع التنبيه الجديد `site-error` في إعدادات التنبيهات).
- **فين تشوفها؟** لوحة الإدارة ← الإحصاءات ← **«أخطاء الموقع»**.

| الملف | الدور |
| --- | --- |
| `src/lib/error-report.ts` | تنظيف البلاغ + البصمة (منطق نقي) |
| `src/app/api/errors/route.ts` | `POST` بلاغ من المتصفح · `GET` الأخطاء المجمّعة (أدمن/مشرف فقط) |
| `src/components/error-reporter.tsx` | يلتقط أخطاء المتصفح العامة (مثبّت في `layout.tsx`) |
| `src/app/error.tsx` | يبعت البلاغ مع `digest` صفحة الخطأ |
| `src/components/admin-error-log.tsx` | قسم العرض في لوحة الإدارة |
| `src/db/schema.ts` · `src/lib/directory.ts` | جدول `directory_error_log` (يُنشأ تلقائيًا مع `ensureSeed`) |
