# الجولة ٢٦ — متابعة تفصيلية لأخطاء المتصفح + زر «تم الإصلاح»

## الفكرة
بعد فلترة ضوضاء المتصفح (الجولة ٢٥)، بقى السجل نفسه شغّال ومحتاج متابعة:
كل خطأ بيتصنّف، ويتقفل بزر واحد لما يتصلح، ويرجع يظهر لو حصل تاني.

## التصنيف (src/lib/error-triage.ts — منطق نقي ومُختبر)
| النوع | مثال | الشرح والخطوة العملية |
|---|---|---|
| `chunk` | `Failed to load chunk /_next/static/chunks/…` | ملف من نسخة قديمة — بيتحدّث تلقائيًا؛ لو اتكرر أعد النشر |
| `webview` | `Java object is gone` | متصفح داخل تطبيق (فيسبوك) — شجّع فتح Chrome |
| `external-script` | `Script error.` | إضافة/حقن خارجي، مش من كودنا |
| `network` | `Failed to fetch` | نت الزائر أو مهلة الخادم |
| `storage` | `QuotaExceededError` | تخزين المتصفح مرفوض |
| `app` | أي خطأ تاني | خطأ حقيقي محتاج مراجعة الكود |

## الحالة
`errorStatus()`: **مفتوح** · **تم إصلاحه** · **عاد بعد الإصلاح** (لو ظهر بعد تاريخ القفل).

## التخزين
جدول جديد `directory_error_resolutions` (fingerprint PK, note, resolved_by, resolved_at)
مع `SCHEMA_VERSION = 2026-11-02.11`.

## الـ API
- `GET /api/errors` — الأخطاء مجمّعة + حالة كل واحد + مين قفله وملاحظته.
- `GET /api/errors?fingerprint=…` — آخر ٢٥ ظهور للخطأ بالـ stack والصفحة والجهاز (للتفاصيل).
- `PATCH /api/errors` — `{fingerprint, action:"resolve"|"reopen", note?}` — للإدارة والمشرفين،
  وكل إجراء بيتسجل في سجل النشاط.

## الواجهة
- شريط علوي: بحث + تصفية (مفتوحة / تم إصلاحها / الكل) + تحديث.
- كل صف: النوع، الصفحة، المتصفح، «قبل ٥ دقايق»، عدد التكرار، شرح الخطوة العملية.
- زر **«تم الإصلاح»** يقفل الخطأ (مع إمكانية كتابة ملاحظة الإصلاح)، وزر **«إعادة فتح»**.
- زر **«تفاصيل»** يفتح شاشة عائمة فيها البصمة والصفحة والجهاز وأول/آخر ظهور وقائمة الظهورات بالـ stack.
- رقم الخطأ المفتوح بيظهر فوق زر «أخطاء الموقع» في صفحة الإحصائيات.
